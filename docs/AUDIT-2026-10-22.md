# Source and release audit — 2026-10-22

## Outcome and scope

This record covers the **0.1.1** maintenance release of MCP Maintainer Tools.
The baseline was the initial public commit
[`aa4a340d531ab1150fea386876c1dd636eed182a`](https://github.com/No3214/mcp-maintainer-tools/commit/aa4a340d531ab1150fea386876c1dd636eed182a).
Review included all project source, tests, packaging metadata, example client
configurations, the GitHub Actions workflow, documentation, and original brand
assets. Findings were reproduced or checked against the implementation, fixed,
and followed by regression checks.

This was an assistant-assisted maintainer source review with automated checks and
limited public-provider smoke tests. It was **not** a hosted Codex Security scan,
an independent penetration-test certification, a formal proof, or an assessment
of the user's other repositories, computer, or accounts.

The project remains an early public release. Its seven tools retrieve research
data over local MCP stdio. They do not scan a repository, patch dependencies,
approve releases, or expose a public HTTP service.

## Findings and changes

The priority labels below describe this project's local research workflow. They
are not CVSS scores or claims of a remotely exploitable service vulnerability.

| Area | Observed problem or gap | Change and evidence | Priority |
| --- | --- | --- | --- |
| Package identity | A plausible deps.dev response for another package could be accepted. Default-version flags also needed type checks. | Verify system and package identity, allowing documented PyPI and NuGet canonicalization only. Reject invalid default flags. Regression coverage in `test_tool_contracts.py` and `test_upstream_integrity.py`. | Medium: result integrity |
| EPSS values | Invalid probabilities, non-finite numbers and invalid dates could reach clients as useful-looking scores. | Require finite scores and percentiles in `[0, 1]`, and valid calendar dates. Preserve accepted values without unnecessary rounding. | Medium: result integrity |
| MCP types and continuation | SDK preprocessing could coerce input types and transform opaque tokens such as the string `"null"`. | Expose strict bounded schemas and disable the SDK's JSON-string guessing only for this server's tools. Test actual MCP dispatch, optional tokens and nested batch inputs. | Medium: query integrity |
| Error privacy | Validation errors and known SDK malformed-message logs could contain supplied argument values. | Sanitize client validation errors and targeted SDK envelope, notification and stream-validation logs. Tests use synthetic private markers and real SDK error paths. Unrelated logging behavior remains intact. | Medium: confidentiality |
| Response resources | Ordinary buffered HTTP requests did not adequately bound a successful provider body or JSON structure. | Stream bodies, cap raw bytes at 32 MiB, refuse unexpected compression before decompression, bound nesting, reject duplicate keys, invalid Unicode and non-finite numbers. Close error/retry streams without buffering their bodies. | Medium: availability and integrity |
| Request state | Implicit proxy/CA environment settings and provider cookies could change request behavior. | Disable both by default; refuse cookies and redirects, require credential-free HTTPS URLs, bound the pool, and offer an explicit trusted-environment opt-in with TLS verification retained. | Hardening: transport and privacy |
| Result provenance | Duplicate/invalid OSV IDs and timestamps on empty local batch work could mislead clients. | Validate identifiers and return `queried: false` without a retrieval timestamp for an empty OSV batch. Preserve provider pagination and absence semantics. | Medium/low: interpretation |
| KEV availability | The canonical CISA endpoint returned HTTP 403 from the validation environment. | Use CISA's documented official mirror only after selected availability failures. Record actual/canonical source URLs and fallback status. Invalid content is still rejected. | Compatibility |
| Installation and metadata | Informational CLI options were missing and the SDK handshake reported its own version. | Add `--help` and `--version`, keep default stdio startup, report application version, and verify an installed wheel from outside the checkout. | Compatibility |
| Delivery and identity | The project needed clearer operating guidance and a consistent public presentation. | Add platform-specific configuration examples, threat model, this audit record, release notes, a brand guide, editable SVGs and PNG exports. Expand reproducible CI checks. | Maintainability |

No finding in this review established remote code execution, arbitrary shell
execution, or a general-purpose SSRF interface. This statement describes the
findings, not an exhaustive guarantee against those classes of issue.

### Runtime dependency advisory scope

`pip-audit` examined an isolated Linux/Python 3.12 environment containing the
resolved runtime dependencies and its pip installer. **30 distributions were
checked; no known vulnerability was reported.** The editable project itself was
explicitly skipped by that advisory lookup and reviewed at source instead.

The resolved direct dependencies were MCP **1.30.0**, HTTPX **0.28.1**, and
Pydantic **2.14.1**. The installer was pip **26.2.2**. This result is a snapshot of
the versions resolved on the review date. It does not cover every future version
allowed by the dependency ranges, every platform, every development tool, unknown
vulnerabilities, or malicious packages without published advisories.

The MCP requirement is constrained to `>=1.30.0,<1.31` because preserving raw
argument types and reporting the application version use two narrow SDK integration
points. The logging adapter also targets reviewed SDK paths. Review these
integrations and rerun protocol/privacy tests before widening the SDK range.

## CI and release reproducibility

The [Checks workflow](../.github/workflows/tests.yml) is configured to run:

- Python 3.11, 3.12, 3.13 and 3.14 on Ubuntu, plus Python 3.12 on Windows and macOS.
- The full test suite with a combined statement/branch coverage threshold of 90%.
- Ruff lint and format checks, Bandit source-pattern checks, source/wheel builds,
  strict Twine metadata checks, and built-wheel CLI/stdio checks.
- A separate resolved-runtime dependency advisory scan.

Actions are pinned to reviewed full commit identifiers. Workflow permissions are
read-only, checkout credentials are not persisted, and the workflow does not
deploy or consume repository secrets. The [workflow run history](https://github.com/No3214/mcp-maintainer-tools/actions/workflows/tests.yml)
is the authority for each commit's remote CI outcome; local results and workflow
configuration alone do not establish a remote pass.

Reproduce the checks using [CONTRIBUTING.md](../CONTRIBUTING.md). A wheel should be
installed and exercised from an unrelated working directory, so the checkout's
`src` path cannot hide missing distribution files. A successful build is not a
PyPI publication; this release is distributed through the repository.

## Publication and brand review

The public-file review used the tracked and non-ignored untracked file list. It
checked for accidental credentials, private runtime paths, unwanted build/cache
artifacts, and active or externally loaded SVG content. Secret-pattern matches
were synthetic test fixtures, not production credentials. This was a targeted
file review, not a scan of unrelated repositories or all account history.

The visual identity uses an original evidence-frame motif and the line
**“Evidence, within reach.”** The asset set includes light/dark icons and
wordmarks, a GitHub banner, and a social card with editable SVG sources. PNG
exports support sharing. The [brand guide](BRAND.md) records color, typography,
usage, contrast checks and claim boundaries. No provider logo, endorsement,
security badge or certification claim was introduced. Generated banner and
social-card previews were visually inspected.

## Remaining boundaries and follow-up conditions

- **No strict whole-request deadline.** Connect/pool waits are 10 seconds and
  individual reads/writes are 15 seconds. An elapsed-body check runs after headers
  and between raw chunks. Slow headers or a blocked I/O phase can delay that check.
  Retries and KEV's separate fallback request add to total elapsed time.
- **No fixed total-memory or global-rate ceiling.** The 32 MiB limit applies to
  one response body. Parsing, output serialization and concurrency use additional
  memory. A shared pool is not a complete quota or multi-tenant isolation design.
- **Provider facts remain untrusted.** Structural validation cannot prove that a
  plausible advisory is true, exhaustive or fresh. Descriptions and links can
  contain prompt injection; the MCP host must keep them as data.
- **Logs require operational care.** The targeted log adapter is not a general
  secret scrubber. Explicit SDK DEBUG protocol dumps can reveal inputs. Custom
  embeddings must install the adapter themselves; official entry points do so.
- **Optional proxy trust changes routing.** Enable environment trust only for
  trusted proxy and CA configuration. TLS verification remains enabled, but the
  chosen configuration affects the network path and certificate trust sources.
- **Repository governance is separate.** At the time of inspection, `main` was
  unprotected and the repository had no rulesets. CI configuration alone does not
  force future merges to wait for checks. This report does not assert enforced
  branch protection, signed releases, or a separate reviewer's approval.
- **Early release.** Compatibility tests and branding do not establish adoption,
  production-scale performance, a response-time SLA, or eligibility for an
  external sponsorship or benefits program.
